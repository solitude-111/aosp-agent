# AOSP agent 运行契约

CLI 的 `run` 经 `mapped_run.py` 提取来源身份与固定目标提交，忽略案例中的历史文件白名单、参考影响结论和验证答案；`diff` 接收原始补丁和可选 donor 身份。二者由映射计划产生实际写入范围，再交给后端。`patches.py` 分解补丁，`sdk_runtime.py` 管理 SDK 会话，`engine.py` 负责单仓证据核实、Git 隔离、补丁导出与验证反馈。

默认 `run/diff` 使用 `ProjectFirstAgent`：先分析完整补丁与轻量目录，再读取选定项目，按带证据的请求扩仓。`batch` 接受四字段 JSONL，经离线来源核实和固定 manifest 目录进入同一前端，逐行串行执行并保存独立结果。单来源保留 run 因果检查后端；多来源使用带来源命名空间的完整单元映射、范围证据及文本迁移后端，不将多个来源伪装成单一提交。仅显式 `--exhaustive-discovery` 使用旧全仓执行器。

```text
输入事实 → 固定提交/独立工作树 → donor hunk 文本检查
                              ↓
                       SDK 只读影响判断
                              ↓
                 Git 引用核实 ← 只读纠正
                       ↓            ↓
                   AFFECTED      UNKNOWN/NOT_AFFECTED 终止
                       ↓
                 SDK workspace_write 迁移
                       ↓
                路径/HEAD/原 checkout 审计
                       ↓
        新生产源码接入审计（含 donor 新增和暂存文件）
                       ↓
                 含新增文件的候选补丁
                       ↓
          独立干净 worktree 重放 + 分层验证 → 失败反馈修订
```

证据摘录必须是指定 Git 版本、文件和行范围中的连续真实片段。该检查不是语义正确性证明。只有 AFFECTED 才允许进入补丁阶段；原始 checkout 的 HEAD、状态和 tracked diff 摘要需保持不变。默认 SDK 执行器使用命名权限配置，原生命令默认拒绝文件系统读取，仅放行阶段工作目录、准入仓库及其确切 Git 元数据/对象库、必要工具运行环境；编辑阶段只放行声明的候选文件。规划阶段不开放目标源码。外部 MCP、连接器、浏览器、额外代理等工具入口分别禁用；不能把原生命令沙箱当成外部工具权限。控制器仍在每回合后审计候选路径和原始源码。

权限配置依赖固定 CLI 的实际协议能力；启动前核实，缺失则失败，不退回普通全盘只读。SDK 类型层未包含的字段通过经核实的底层协议适配发送，每轮显式选择读/写配置。受控读取脚本与其 Python 模块放在本次运行目录中，不为导入代码开放整个 agent 工程或用户目录。macOS 的 Git 动态库使用已核实的真实库路径；受控 Git 不继承用户或系统配置。

每轮结束、错误或取消时清理 SDK 登记的后台终端；清理失败关闭运行时并拒绝接受该轮结果。权限切换本身不能撤销旧进程的写权限。原生测试覆盖未结束的终端和普通 shell 后台子进程，不宣称已经证明任意脱离进程管理的进程都被隔离。仍需在目标 Linux 环境和真实模型工作流验证。仓库路径权限也不是 Git 对象版本授权：证据版本核实和固定对象读取工具仍不可省略，SDK 工具启动后的预算计数尚不是执行前拦截。

验证配置不作为参考答案注入初始模型 prompt。控制器只把实际失败输出回传。检查可声明验证阶段和预期产物，结果保存 argv、退出码、日志及产物哈希。新文件与已暂存修改均进入补丁；新增生产源码必须有基线已有函数的新增调用或 Manifest 组件注册证据，否则在验证前拒绝并进入重试。donor 原生新增不豁免。测试与 fixture 单独分类，不可用作生产接入证据。拒绝的候选单独留存，旧补丁路径和验证缓存失效。导出后在全新 target worktree 重放，空补丁不能算成功，验证不得悄悄修改被验证候选。没有检查或没有运行检查分别标明 NOT_CONFIGURED/NOT_REQUESTED。

验证记录包含具体检查身份、命令及直接文件内容、位置、环境、目标提交、候选补丁和依赖上下文；这些信息不能证明脚本导入、配置文件和子程序的完整输入集合未变，因此目前所有验证检查都重新执行，不复用旧 PASS。固定提交的 Git 对象读取使用独立缓存。单仓和多仓共用 production_build_v1：所需仓库必须有本次候选、本次调用的生产构建/apply/restore 成功凭据，且全部已配置检查通过；普通命令成功不再足够。缺少覆盖的仓库写入 policy，旧产物留档后必须重新生成。VALIDATED 不构成运行时安全证明，凭据也不独立证明任意配置命令为生产编译器。

映射执行器统一延后子仓复核，待最终组合形成后再运行只读业务影响分析，适用于 VERIFIED、VERIFIED_SEQUENCE 和文本来源。单仓直接执行入口保留自己的复核。实际验证状态、来源序列和整个候选组合传入复核；不再在提示中提前声称构建或契约检查通过。单仓/组合复核失败显式记录 INCOMPLETE；成功记录绑定候选或整个组合摘要，组合任一成员变化都会重新复核。它不提升构建或运行时证据等级。

delivery.py 的 build_and_review_v1 在保存和返回记录时统一计算构建、复核和交付字段。构建合格但当前候选复核缺失、失败、过期或中高风险时，总状态为 NEEDS_REVIEW/退出码 7，构建 PASS 保留。低风险复核必须覆盖所有补丁仓库并绑定各补丁及完整组合摘要；只有它和构建证据同时满足时才返回 VALIDATED/READY_FOR_HANDOFF。普通单仓联合检查不能抹除该仓已有的生产构建覆盖，但必须通过且属于同一组合；多仓仍要求联合构建覆盖。失败、恢复屏障和不完整发现不会被旧复核升级。NEEDS_REVIEW 不触发自动重跑，也不阻断独立的后续批次行。

新文件接入检查使用 Python AST 和固定版本 tree-sitter 的 Java/C/C++/Kotlin 语法树，排除已实现的恒假分支、短路、提前返回及延迟函数体。Java/C/C++ 的字面 switch 检查区分 colon 分支贯穿、break/return 和 Java arrow 分支；Kotlin when 不按贯穿处理。未知条件/标签保留条件信息，尚无适配的 Python match 或特殊嵌套 C 标签不获得接入信用。

生产入口必须提供新增文件路径和实际源码；名称集合只能用于诊断，不能满足导出门禁。`binding.status=RESOLVED_LEXICALLY` 记录具体目标文件、声明、依据及假设。Python 要求显式模块/成员导入，支持别名和包内相对导入，拒绝参数、局部变量、属性替换及错误模块遮蔽；Java/Kotlin 核对声明、包名、显式导入、静态方法/对象/companion 和受支持的 JVM 静态桥接。native 自由函数使用实际函数定义的外部名称，不依赖文件名；同名函数指针、旧本地定义、仅原型或新翻译单元中的 static 定义不能冒充新增外部实现。Manifest 按完整组件类名核实。

已存在调用的导入发生变化也可构成接入边，但新增无关导入不能获得信用。返回证据仍假设既有函数入口被调用，`production_reachability_proven=false`；编译器重载解析、产品 classpath/native 链接、Python 导入根及动态 rebinding 等假设单独保留。此受限静态绑定不是全程序、任意动态分派或运行时安全证明；反射、JNI、一般实例数据流和未支持语言/头文件接入形式需要后续适配，不能退回名称匹配。

artifact_roles.py 不再按测试文件名/目录豁免新增源码，也不把未知后缀默认为非源码。测试角色依赖固定基线祖先 Android.bp 中可解析的测试消费者，或受支持 Python 断言结构及到实际修改的既有实现的绑定；候选构建文件不参与授权。祖先查询只用于正向测试消费者证据，不声称覆盖整个产品。已有生产消费者冲突或读取/解析不完整时，不据此授予测试豁免。角色分类本身不运行测试、不提供生产修复信用；源码义务不能被辅助测试、配置或数据替代。上游完整新增测试需另核实受支持的断言/JUnit/kotlin.test 定义，不因目标测试构建声明就把生产来源重新分类。缺少新文件时无额外角色读取，固定基线的成功读取按路径缓存，失败不缓存为缺失。

同一角色核查也用于基线已有调用方：固定测试消费者或受支持测试定义不能为新增生产 helper 提供接入信用，即使调用方名称不含 Test。排除证据保存在 excluded_test_callers。其余调用仍保留“既有函数入口被调用”的局部分析假设，不能把未识别为测试等同于已证明产品可达。

自动构建规划分别记录测试模块和生产模块。测试模块覆盖不能补足 `production_uncovered`；可能使用受改文件但未解析清楚的生产模块进入 `unresolved_consumers`，不能借其他简单模块的成功隐去。字面源码/默认项/条件分支可证明无关联的模块不作为阻断项；不能解析的源码配置仍保守保留。该索引没有求值完整 Soong 产品配置，显式构建覆盖项仍由配置方负责选择。

未请求验证、仅做影响分析、未配置构建器、没有改动文件，或显式覆盖构建检查时，自动构建查询保持 DEFERRED，不遍历该项目全部 Android.bp。查询确实启用时仍覆盖项目内兄弟消费者，不能仅找到最近的测试模块就停止。

diff 可选固定 donor commit/parent：先比对直接父子关系与输入 diff 的路径、行号、内容和文件生命周期信息，再开放本地只读历史工具。没有 donor 时明确降级为 diff 行证据。run/diff 共用版本目录路径归一化，检索评分不替代语义关系核实。

多 Git 项目由映射计划选择，分别建立工作树和编辑范围，多仓构建使用固定补丁包联合应用、验证与恢复。单仓通过不能代替联合通过。`--repository` 可重复指定初始项目范围，不枚举未选项目，之后仍允许带证据扩仓。`--inspect-only` 不启动模型：仅单项目或已有元数据线索可确定范围时读取；否则报告 `INSPECTION_REQUIRES_PROJECT_SCOPE`，不自动全仓扫描。当前没有通用 Android 设备 runner；构建所有权的字面解析也不等于完整 Soong 产品配置求值。

受控源码工具在多仓模式使用 `target:<repository-key>` 和该项目固定 SHA，历史工具显式指定 `--target-repo`，不默认选择第一个仓库。读取失败与路径不存在分开报告，缺路径不能作为功能不存在的证明。映射层的 `NOT_AFFECTED` 和 `ALREADY_FIXED` 均需独立只读复核；后端与已建立的受影响映射矛盾时记录 UNKNOWN 和重规划需求，不直接发布否定结论。

`locate-symbol` 默认检索 Java/Kotlin、C/C++/Objective-C、Rust、Go、Python、接口和汇编源码扩展名，可用重复的 `--language` 缩小范围。输出及使用日志保留搜索范围和 FOUND / NOT_FOUND_IN_SCOPE / READ_FAILED；范围未命中不是符号或等价操作不存在的证明，读取失败返回非零。预扫描把读取失败单列，不加入兼容字段 `missing`；该旧字段只表示范围内的字面未命中。

普通验证器在成功、非零退出、超时、输出超额和取消后都清理整个进程组，再返回控制器核验产物及释放源码租约。无法确认清理则抛出恢复屏障，阻断后续仓库和批次行，不能作为普通单案失败跳过。stdout/stderr 由独立读取线程排空，内存中每路保留至多 1 MiB 原始字节的首尾片段并标明截断，不再生成全量临时捕获文件。单次命令两路累计超过默认 64 MiB 时请求停止，返回 125；TERM 宽限期继续读取但有界保留输出，使恢复逻辑能打印并完成。即使进程先返回 0，随后读完的输出超过上限仍是失败。该限制不是整个任务日志/构建产物的总容量，也不是对任意脱离进程组 daemon 的隔离保证。

`ProjectFirstAgent` 的每轮建立独立记录和候选工作区，只共享固定提交的对象缓存。按需文件读取不会把同名文件视为完整匹配，仍保留选定项目内的有限符号检索。构建发现扫描选定项目的 Android.bp 元数据，包含兄弟目录的 filegroup 使用方；不因局部测试模块覆盖源码就停止检索，也不声称已经覆盖未加载项目或完整产品配置。

固定对象缓存默认限制受管序列化数据总量 256 MiB、单条 16 MiB、1024 条；小型配额元数据与锁不计入数据额度。flock 覆盖读取、最近使用时间更新、淘汰和临时写入；实际 Git 读取在锁外执行。命中不反复扫描目录，写入按最近使用顺序腾出完整临时写入空间。共享目录采用请求过的最严格配额，已有写入者不能恢复宽松上限；扩大容量需使用新缓存目录。超大结果不缓存，旧损坏/超大条目及遗留临时文件在准入时处理。维护最多使用短时间预算；缓存慢、不可用或写入失败时，本实例禁用缓存并保留正常源码读取，错误不作为不存在。旧目录未成功完成配额准入时记录 quota_adopted=false，不能声称旧存量已经清理到上限。缓存不负责清理无关文件；这些策略不约束源码树或编译产物。

范围检查要求逐变更单元的入口、状态流、安全条件及依赖证据义务，引用所有映射区域和已有 donor 两侧，依赖项目必须与证据一致。代码义务须锚定函数区域；数据配置和测试变更可以使用相应映射。该结构检查仍不能证明模型语义推理正确，独立排除复核不可省略。

标准库行为没有按命名空间获得“已验证”豁免。影响报告中的 platform_semantics 需要分别提供 relied_at_evidence 调用处和 implementation_evidence 目标版本实现：精确源码出处、受支持语法中的具名定义及可执行函数体均需核查。Java 类级 API 需引用构造函数，方法级 API 需引用对应方法；Kotlin 方法、C/C++ 自由函数支持有限的定义识别，不支持的形式保留未解决。实现不能来自 donor 版本，不能复用调用处或替代核心映射位置的因果证据。多仓实现证据只读取已准入仓库的固定提交，不扩大编辑范围；按来源单元隔离。

platform_behavior_evidence 只报告 SOURCE_GROUNDED/NOT_USED，semantic_correctness_proven 和 runtime_dispatch_proven 始终为 false。模型对源码行为的解释、重载/链接/动态分派以及所有相关依赖的完整性仍需判断，具名定义不等于语义证明。关键实现不可获取时要求补充有界只读范围或返回 UNKNOWN，不把标准库名称、模型记忆或自由文本解释当作已证实行为。

生产阶段使用控制器动态工具代理：关闭原生 shell/apply_patch 及外部工具入口，只暴露 aosp_source、aosp_read_file、aosp_list_files、aosp_write_file、aosp_replace_text。固定 Git 仓库/提交由控制器元数据授权，模型不能传任意命令或 Git argv；候选及元数据文件读取与原始固定版本源码读取分开。文本 diff 也生成目标源码工具上下文；跨标签分析显式授权两个固定提交。工具源码/解释器的 OS 读取权限不自动成为模型文件工具的读取权限。

代理在执行前申请操作额度和结果容量，内部每条 Git 查询也申请额度。模型文件读取及 Git stdout/stderr 使用共享字节预算（默认 64 MiB 的保守预留），每次结果最多 64 KiB，单文件及单条 Git 捕获最多 32 MiB；日志、控制器自身读取和对象缓存的磁盘总量不在该字节额度内。文件读之前按大小预留，Git 输出按块预留；超额不将部分输出当完整证据。预算对象显式传给 SDK 读取线程，线程安全计数；不靠工具开始事件事后拦截生产工具。

写入仅允许当前回合授权的确切候选文件，必须匹配完整文件摘要（新文件用 ABSENT）；文本替换必须唯一匹配。目录 FD 与 O_NOFOLLOW 防止通过软链接改到范围外，临时文件原子替换保留普通执行权限。只读回合、重复/旧回合工具请求均不能写入。回合结束或取消后先取消并排空控制器回调、终止其 Git 进程组，再清理 SDK 终端；未知审批请求默认拒绝。该机制不声称对任意外部进程、挂起的网络文件系统内核调用或整个主机提供隔离。

调查预算与控制器 Git 操作共享；迁移阶段保留自身每回合截止时间、运行时累计 I/O 预算和总模型回合限制，构建及强制恢复不由模型工具执行。结构化输出纠正仍消耗模型回合预算，并共享原调用截止时间。仅无显式 read_scope 的底层 SDK 诊断接口保留旧工具事件计数；所有 agent 生产入口传入阶段范围，OS 原生权限测试使用测试内诊断适配器，不是生产回退路径。

每个任务和批次持有 OS 文件锁作为进程租约。`status` 分别报告保存阶段与锁状态，不把旧状态文件当活进程。SIGINT/SIGTERM 触发 SDK/验证子进程清理并保存 CANCELLED；验证进程先收到 TERM 和恢复宽限期。明确的 `resume` 检查原输入校验和、原始源码基线及构建恢复记录，拒绝并发或未核实的恢复，然后在新目录从原固定输入和已选提交重新映射、生成候选、执行验证。旧候选和旧 PASS 不复用。批次恢复保留已终态行，只继续取消中或未开始行；显式恢复获得新的有限预算，不是无限自动重试。

项目优先任务/批次及旧 diff、dataset、直接后端执行入口持有独立于运行目录的源码树租约，比较 canonical 根目录及父子包含关系；串行子任务显式继承父租约。批次恢复先取得所有旧子任务租约并保持到新批次退出，不使用一次 liveness 查询替代持有锁。`LeaseBusy` 和 `RecoveryBlocked` 是整个批次的阻断条件。恢复创建的新执行记录在开始运行前写回当前行，避免异常退出后只留下旧执行路径。验证进程及受控 builder 通过 `pass_fds` 继承源码租约；关闭控制器句柄不主动解锁，最后一个持有者退出才释放。租约协调范围为同主机同 OS 用户下使用该入口的任务，外部进程和绕过这些入口的任意低层操作不因此获得全面隔离保证。

执行租约在旧 diff 构造阶段即覆盖 inventory，并在开始执行时重新核实原始基线，防止两阶段之间的源码漂移。直接后端的 prepare、inspect、run、export_patch 和 verify 使用相同保护。同一控制器内部同步调用可复用操作上下文；不同控制器必须显式传递租约，不从全局当前租约自动继承，另一线程也不能复用该操作上下文。

恢复记录保存前向关联和新记录的反向关联；读取链时持有每个记录租约，校验输入身份、反向关联及环路。旧记录阶段保持原样，通过链找到最新阶段。批次也使用相同机制，单案已在外部显式恢复并结束时批次保留该终态，不再执行。准备好的后继记录在发布前保存调用参数和固定 catalogue；缺失记录、损坏关联或无法核实恢复状态均阻断，不退回祖先重跑。

单来源后端和多来源映射共用 impact_proof.CausalityChecks。project-first 和 VERIFIED_SEQUENCE 的映射判断必须提供 proof_groups，逐来源命名空间覆盖所有变更单元；核心变更保留自身故障、修复和目标危害引用，辅助/测试/配置变更用明确的 support_links 保留自身证据及核心关联。缺失证据停止为 UNKNOWN，引用核实不等于语义或运行时安全证明。

当前 checkout 目录由实际选中 XML、include 和有序本地覆盖构成并保存各文件摘要；固定发布版本继续读取固定 manifest 提交。当前配置解析失败不再隐式退回目录遍历。初始规划和后续重规划的结构、项目键、单元遗漏错误均有限纠正；失败记录保留，纠正回合共享原模型/调查预算，耗尽不进行源码扫描。

所有验证仅限防御性源码检查、正常功能测试和修复回归；不构造、下载或执行利用 PoC。运行结果准确报告实际覆盖范围，不从编译或文本可应用性推出产品安全结论。

跨版本继承命令只报告仓库版本兼容性，`validation_inherited=false` 明确表示没有导入旧验证凭据。Git 读取失败显式报错，空文件范围拒绝；不同版本的选中文件相同也不能证明依赖或配置相同。修改行号不重叠要求重新验证。模型建议 INHERIT 在缺少完整依赖/环境身份及验证凭据时降为 CONDITIONAL；同一提交的 INHERIT 只表示代码版本相同，不表示构建环境相同或漏洞已修复。

跨版本分析的 API 与 CLI 统一在外部 `run_root` 下创建唯一输出目录，事件与结果均不再写入补丁所在目录。输出根按实际路径解析后必须在原始源码树之外；默认 `cwd/runs/inherit` 不满足时须显式指定。词法提示与验收命令也分开：自动 donor 符号只保存为 `validation_plan.provenance`，不产生硬性 `source_contract` 检查或 PASS 信用。显式配置的检查继续参与完整验收策略，功能检查失败、生产构建证据不足或因果账本缺失不会因词法提示而放行。

控制器受管输出由 output_budget 的持久累计预留计数约束。默认根任务 256 MiB，嵌套任务及正常 resume 继承祖先额度；跨进程 flock 覆盖状态校验、预留和输出写入，锁等待最多约 2 秒。写前预留，失败或覆盖不退款；状态文件损坏、软链接逃逸及 I/O 故障不能降为无限额。普通输出保留额度之外另留 min(总额/8, 4 MiB) 的控制记录空间及 8 KiB 配额元数据空间。额度耗尽后最小 run/batch 记录标记 BLOCKED、UNKNOWN、record_compacted；控制记录空间也用完时，以持久 exhausted 标记阻断 status/resume，不能读取旧成功记录继续执行。

SDK 主线程在调用前和事件消费后检查输出额度；日志线程只设置失败/取消信号，避免日志写入异常中断 SDK 的 interrupt/close。单仓和联合验证在启动检查前核查额度，实际验证进程必须先完成清理/恢复，再保存受限日志。源码恢复回执不属于普通额度。该计数只覆盖控制器管理的 payload，不是磁盘 block、目录数或全工作区配额；源码/候选 Git 工作树、缓存、外部构建产物和恢复回执另有所有权。未创建任务预算的低层诊断写入仅有单文件 32 MiB 限制，不作总额保证。

后端从 SDK 事件日志增量收集控制器顶层 broker_source_usage 凭据，并与旧原生命令诊断标记按 UID 去重后写入 tool-usage.jsonl。模型文本内的 JSON 或标记不提供这种出处。失败和不可用记录可以保留作诊断，但明确拒绝、READ_FAILED、PATH_ABSENT、NOT_FOUND_IN_SCOPE、NOT_AVAILABLE 不提供正面 hunk 证据。工具凭据只证明受控读取发生；相关仓库、路径、变更单元和独立语义检查仍决定证据能否支持判断。

逐 hunk 实现检查先尝试将 donor 的完整旧文本绑定到固定目标版本。能唯一定位时，候选必须触及每个实际变更块的位置；上下文行仅用于定位，同文件另一处修改不能代领信用。映射范围仍是外层边界，位置在范围之外或重复旧文本无法消歧时拒绝。固定目标分析和稀有行索引按文件复用，重试不重新读相同 blob。Git blob 读取失败只有在固定树明确没有该路径时才视为缺失，否则形成恢复屏障。无上下文的新增代码声明 already_present，需要精确映射范围与完整有序新增行一致，或整文件一致，不能拼凑散落各处的相同行。

already_present 的反证检查按完整新增块核对：原代码仍在时，只在同一函数的另一分支发现某一条新增行不足以排除该 hunk；新增块需位于覆盖锚点的结构路径。同一路径上的完整条件防护仍可通过。这里使用结构路径，不能证明任意控制流、宏展开、动态分派和运行时语义。donor 与目标旧文本因版本差异无法绑定时，仍由既有固定映射承担位置选择，本检查不声称解决任意跨版本等价性。

构建元数据的静态求值由 blueprint_literals 承担，与模块归属和最终构建验收分离。父目录作用域先完成求值再传给子目录，继承值不能重赋或追加；本地变量只有未被引用时允许 +=，包括通过别名引用后的修改也拒绝。列表、字符串及映射拼接均有工作额度，表达式深度有界。错误文件不导出部分模块/变量，父作用域错误阻断子文件继承。该层不运行 Go/Soong、不接受模型生成的配置作为验收来源，也不声称求解产品条件、namespace 或 include；对应缺口继续为 UNRESOLVED。metadata_inputs 和目标提交标识将计算结果绑定到实际读取的配置。

build_metadata 在默认固定版本读取流程中缓存解析后的模块事实、静态限制与配置摘要，使用现有受管对象缓存的锁和存储额度。缓存身份包含固定仓库/提交、解析实现与资源策略；环境读取失败不持久化，冷索引仍包含所选项目的兄弟目录消费者。温索引无需重新枚举或读取构建配置，但归属判断每次针对当前文件重新计算。它不能作为产品构建图、候选编译覆盖或验证 PASS 的缓存。
